# UAT checklist: parity with the Apps Script tracker

Purpose: prove, on the deployed Fleetbase, that the Service Tracker gives the same answers as the original tracker (`src/Index.html`) and that the new things (roles, offline, FleetOps links) behave. Every expected number below is **extracted from `service-tracker/server/tests/fixtures/expected.json`**, which was generated by executing the original JavaScript functions (`calcVisit`, `stopInfo`, `svcInfo`, `nextDueOf`) in Node with the time zone pinned to Asia/Riyadh. The PHP engine reproduces them (3,045 assertions, run in CI). What is **not** yet proven is the same result through the deployed controllers, database and UI: that is what you are testing here.

How to use: do the sections in order on a scratch company (or the trial company before any real data exists), tick the `Result` column (`P` / `F` / `n/a`), put initials and date, write failures in the last section. Items marked **[auto]** are also covered by `ops/smoke/smoke.sh` (which has never run against a real server), so a green smoke run does not replace doing them once by hand.

Tolerance: hours are compared to 2 decimals (the tracker rounds the displayed value; the engine keeps full precision and the importer uses a 0.011 tolerance). Money is SAR with 2 decimals (integer halalas stored).

Stage names, in order: 1 Pickup wait (LSA arrival to pickup), 2 Transit to 1st vendor, 3 Approval wait, 4 Vendor work, 5 Between vendors, 6 Return transit. Owners: stages 1, 2, 5, 6 = "Our team"; stage 3 (approval wait) = "Splendor" (the client-side approver in the original tracker; whether Splendor stays a named party is an open decision); stage 4 = "Vendor". Vendor slots in `perVendor`: Local Mechanic, Petromin, Tyre Vendor, Other Specialist.
